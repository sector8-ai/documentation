Connect your application to Sector8, evaluate one proposed action before dispatch, honor the decision, and confirm the integration worked before you write more code.

Telemetry can follow later. Telemetry alone is not onboarding success.

## What you need

- A Sector8 runtime API key
- A Sector8 client ID
- Python 3.10+, Node.js 18+, or a runtime that can call `POST /api/v1/evaluate`
- Access to the application path where you can block dispatch on non-`ALLOW` decisions

<Info>
Contact [support@sector8.ai](mailto:support@sector8.ai) or [book a demo](https://sector8.ai/contact) if you still need your runtime credentials.
</Info>

Public docs use the production host `https://sdkapi.sector8.ai`. Use the endpoint and credentials issued for your environment.

## Recommended first run

<Steps>
  <Step title="Set your credentials">
    Inject credentials through the environment. Do not commit runtime keys to source control.

    ```bash
    export SECTOR8_BASE_URL="https://sdkapi.sector8.ai"
    export SECTOR8_API_KEY="YOUR_API_KEY"
    export SECTOR8_CLIENT_ID="YOUR_CLIENT_ID"
    ```
  </Step>

  <Step title="Confirm the gate is reachable">
    ```bash
    curl -s "$SECTOR8_BASE_URL/api/health"
    ```

    If health fails, do not route live actions until the endpoint is reachable.
  </Step>

  <Step title="Pick one evaluate path">
    Use one of these guides and call `evaluate` before dispatch:

    - [Quickstart](/guides/quickstart)
    - [Python SDK](/guides/python-sdk)
    - [TypeScript SDK](/guides/typescript-sdk)
    - [Non-MCP integration](/guides/non-mcp-integration)
    - [Guard MCP Server](/guides/mcp-server)
  </Step>

  <Step title="Honor the decision">
    Your first successful run should evaluate a proposed action and then:

    | Result | Runtime must |
    | --- | --- |
    | `ALLOW` | May dispatch |
    | `DENY` | Block; do not dispatch |
    | `REVIEW` | Pause / route to approval; do not dispatch |
    | Missing, unknown, error, or timeout | Fail closed; do not dispatch |

    Sector8 returns the verdict. Your application owns enforcing it at the dispatch boundary.
  </Step>

  <Step title="Verify the result">
    Confirm:

    - health responds for your environment
    - one real `evaluate` call returned a decision artifact
    - your runtime dispatched only on `ALLOW`
    - `DENY` / `REVIEW` / unknown / error paths did not execute
    - the decision artifact includes `reason_code`, `decision_trace_id`, `evidence_hash`, and `policy_version_id`
  </Step>
</Steps>

<Check>
You are done when one real evaluate-before-dispatch proof succeeds against your issued endpoint, your runtime honors the decision, and you can trace the decision artifact in Sector8.
</Check>

## Common mistakes

<Warning>
Use `https://sdkapi.sector8.ai` for public production examples. Do not paste real runtime keys into docs, tickets, chat, or source control.
</Warning>

- Treating connection health or telemetry as proof of enforcement
- Logging an LLM event without calling `evaluate` before tool dispatch
- Treating `REVIEW` as a generic deny instead of an approval pause
- Hardcoding `SECTOR8_API_KEY` or `SECTOR8_CLIENT_ID` in source
- Forgetting a stable `session_id` on governed tool calls
- Assuming unconnected tool paths are covered automatically
